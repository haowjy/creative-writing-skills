# Zoom Out

Step back from the task to the area around it: what it's for, how its parts
connect, why it's shaped this way, and the words the project uses for it.
Then return to the task with that picture.

Start with the docs, and read them yourself: the `AGENTS.md` and
`.context/` files along the path, the KB pages on the subject, the
project's vocabulary. In an area too large to search yourself, have
`@explorer`s find what's related first, then read what they point to.
Spawn `@session-miner` when no doc says why the area is shaped this way.

Write the picture down as one map, not a stack of reports:

- **What this is**: the area's purpose and boundaries, in two or three sentences.
- **Structure**: the parts and interfaces that matter and how they connect.
- **Why it's like this**: the decisions and constraints behind the current shape.
- **Vocabulary**: the terms needed to talk about it precisely.
- **Open threads**: gaps, debt and unresolved questions.

Where sources disagree, the thing itself (the code, the data, the
manuscript) shows its current state and the recorded direction shows
intent. A doc that misdescribes the current state is stale; a gap between
the current state and the recorded direction is a divergence. Note either
in the map.
